# 08 计算规则（汇总版）

> 本文档基于当前代码实现（`internal/dagcalc`、`internal/api/v3`）整理。
> 
> 目标：统一「正向计算 + 智能调整（反向计算） + 无法调整提示」的规则口径，作为后续维护基线。

---

## 1. 统一前置口径

### 1.1 数据范围
- 计算按当前年月（`config.current_year` + `config.current_month`）执行。
- 指标计算使用两类企业表：
  - `wholesale_retail`（批发/零售）
  - `accommodation_catering`（住宿/餐饮）

### 1.2 住餐“零售额”口径
- 住宿/餐饮不直接使用 `revenue_*` 参与限上社零额。
- 住餐零售额统一按：
  - 当月：`food_current_month + goods_current_month`
  - 累计：`food_current_cumulative + goods_current_cumulative`
  - 上年同口径同理。

### 1.3 增速计算口径
- 增速统一公式：`(本期 - 同期) / 同期 * 100`。
- 当“同期=0”时：
  - 在派生字段重算中置为 `-100`（表格字段口径）；
  - 在指标层面（聚合计算）按 0 处理（避免除零），并在智能调整阶段给出无法反推提示。

---

## 2. 16 项指标计算规则

### 2.1 指标组一：限上社零额（4项）
1. `limitAbove_month_value`：
   - `SUM(批零 retail_current_month) + SUM(住餐 food_current_month + goods_current_month)`
2. `limitAbove_month_rate`：
   - 以上当月口径与上年当月口径同比
3. `limitAbove_cumulative_value`：
   - `SUM(批零 retail_current_cumulative) + SUM(住餐 food_current_cumulative + goods_current_cumulative)`
4. `limitAbove_cumulative_rate`：
   - 以上累计口径与上年累计口径同比

### 2.2 指标组二：专项增速（2项）
5. `eatWearUse_month_rate`（吃穿用增速）
   - 仅在 `wholesale_retail` 内，筛选 `is_eat_wear_use=1` 后按当月同比计算
6. `microSmall_month_rate`（小微增速）
   - 仅在 `wholesale_retail` 内，筛选 `is_small_micro=1` 后按当月同比计算

### 2.3 指标组三：四大行业增速（8项）
- 批发/零售：使用 `sales_*` 口径
- 住宿/餐饮：使用 `revenue_*` 口径
- 每个行业 2 项：当月同比 + 累计同比

### 2.4 指标组四：社零总额（2项）
15. `totalSocial_cumulative_value`
16. `totalSocial_cumulative_rate`

社零总额 = 限上累计 + 限下累计估算值。

## 3. 新增规则 08：限下累计估算复合规则（已内化）

> 这是对原“仅按小微增速估算限下”的补充。

### 3.1 规则定义

#### 规则08-1：上月限下增速
`上月限下增速 = 上月小微增速 * 小微权重 + 上月吃穿用增速 * 吃穿用权重 + 上月抽样增速 * 抽样权重`

#### 规则08-2：本月限下增速变动量
`本月限下增速变动量 = (本月小微增速-上月小微增速)*小微权重 + (本月吃穿用增速-上月吃穿用增速)*吃穿用权重 + (本月抽样增速-上月抽样增速)*抽样权重 + 全省限下增速变动量`

#### 规则08-3：本月限下增速
`本月限下增速 = 上月限下增速 + 本月限下增速变动量`

#### 规则08-4：本月限下累计估算
`本月限下累计 = 上年限下累计 * (1 + 本月限下增速/100)`

### 3.2 配置来源
- `last_year_limit_below_cumulative`
- `small_micro_rate_prev`
- `eat_wear_use_rate_prev`
- `sample_rate_prev`
- `sample_rate_month`
- `weight_small_micro`
- `weight_eat_wear_use`
- `weight_sample`
- `province_limit_below_rate_change`

### 3.3 默认值
- 权重缺失时默认：`0.3 / 0.3 / 0.4`
- 其他缺失配置默认 `0`

## 4. 智能调整（反向计算）规则

### 4.1 目标处理
- `targets` 每个目标值先执行四舍五入（整数口径）。
- 非法数字（NaN/Inf）直接跳过并返回提示。

### 4.2 基础约束
- 目标值为负时按 0 处理（值类指标）。
- 累计类调整不能低于“历史累计下限”（可达最小值），否则按可达下限执行并返回提示。

### 4.3 分配算法
- 调整不是平均分，而是“基值占比 + 规模占比 + 随机扰动”的权重分配。
- 权重核心：`0.5*行业基值占比 + 0.5*规模权重占比`。
- 扰动：`0.7 ~ 1.3`。
- 分配结果按整数落位，并做总量差额回补，保证合计命中目标。

### 4.4 社零总额目标反推
- 当目标是社零累计值/增速时：
  1) 先按规则08算当前限下累计；
  2) 计算总量差值 `delta`；
  3) `delta` 50% 分给限上累计、50% 分给限下累计；
  4) 限下目标反算写回 `last_year_limit_below_cumulative`，确保下次计算可追溯。

## 5. 无法调整提示规范（统一格式）

### 5.1 统一文案模板
当智能调整出现“无法调整/不可达/被跳过”等情况时，提示文案统一为：

`根据{规则名}规则无法调整{指标}数据，建议{操作建议}`

### 5.2 已覆盖场景（示例）
- 可调数据为空
- 同比基数为 0（无法反推增速）
- 目标值非法
- 指标不支持
- 目标值与当前值一致
- 目标变化过小（取整后无变化）
- 目标低于可达下限
- 调整后仍未达到目标（仅可达区间内）

### 5.3 前端展示
- 前端统一按 `notice.level + notice.message + notice.suggestion` 弹 toast。
- 不同场景均遵循同一文案结构，避免“有的说原因、有的只说失败”的不一致问题。

---

## 6. 与历史实现的关键差异

1. **限下估算升级**：
   - 历史：仅 `上年限下累计*(1+小微增速)`
   - 现在：按规则08使用“小微/吃穿用/抽样/全省变动”组合估算

2. **社零反推一致化**：
   - 历史：社零反推与正向估算口径存在偏差风险
   - 现在：正向计算与反向调整都复用规则08的限下估算

3. **失败提示标准化**：
   - 历史：提示语风格不统一
   - 现在：统一“根据xx规则无法调整xx数据，建议xx”格式

## 7. 待业务确认项（后续可选）

- 小微/吃穿用企业身份是否必须“互斥”由系统强校验（当前按标记字段计算，不强制互斥）。
- 零销比的行业约束（批发/住餐 ±1%、零售接近100%）是否要升级为硬约束并内化到智能调整。
- 社零总额反推中 `delta` 的“限上/限下”分摊比例是否继续固定 50/50，或改为可配置。
