# 联动预览算法说明

> 说明：本文描述联动预览的构图、坐标、影响范围计算与接口协议，便于复核“全量联动、全量标记”的实现一致性。

## 1. 构图输入

- 企业数据：批发零售（WR）与住宿餐饮（AC）明细记录。
- 模板索引：从嵌入 Excel 模板读取行业码与行号映射。
- 指标列表：16 项指标 ID 固定枚举。

## 2. DAG 节点与边

### 2.1 企业字段联动（明细层）

- 销售额、零售额增速/增量/环比等派生字段与源字段建立依赖。
- 当月 → 累计：`CurrentMonth → CurrentCumulative`、`LastYearMonth → LastYearCumulative`。
- 零销比：`salesCurrentMonth + retailCurrentMonth → retailRatio`。
- 住餐拆分：`food/goods → retail`（零售额由食品+商品两部分构成）。

### 2.2 行业聚合与全局汇总

- 企业字段 → 行业聚合：按行业类型汇总销售/零售当月与累计。
- 企业零售额 → 全局汇总：用于限上零售额、吃穿用、小微等汇总指标。

### 2.3 指标联动

- 行业/汇总节点 → 指标节点：16 项指标由行业或汇总节点推导。
- 指标间依赖：社零额累计值、累计增速由限上与相关子指标组合。

### 2.4 反向联动（用于预览提示）

为满足“点击派生字段时高亮潜在输入”，补充反向边：

- 增速/增量 → 源字段（当月/上年/累计）。
- 住餐零售额 → 食品/商品拆分字段。
- 指标 → 明细字段（按指标所属行业与口径回溯到企业字段）。

## 3. 坐标映射

### 3.1 UI 坐标

- 前端行标识：`wr:{id}` / `ac:{id}`。
- 前端列标识：`ColumnKey`（与明细表列一致）。
- UI 锚点解析为 `wr|ac:{id}:{field}` 形式的节点 ID。

### 3.2 Excel 坐标

- 行号：读取模板列 C 的行业码，按 `RowNo` → `ID` 排序绑定。
- 列号：按 WR/AC 的字段列映射表固定映射。
- 指标坐标：汇总表（定）与行业表的固定单元格。

## 4. 影响范围计算

### 4.1 算法

- 从锚点节点出发。
- 同时沿正向边与反向边进行 BFS，直到遍历完所有可达节点。
- 将可达节点映射为 UI 坐标、Excel 坐标、指标 ID（若存在）。
- 结果按节点 ID 排序，保证前端渲染稳定。

### 4.2 输出结构

```
ImpactNode {
  nodeId: string
  ui?: { rowId, columnKey }
  indicatorId?: string
  excel?: [{ sheet, cell }]
}
```

## 5. 接口协议

- 接口：`POST /api/linkage/preview`
- 入参锚点（3 选 1）：
  - UI：`{ ui: { rowId, columnKey } }`
  - 指标：`{ indicatorId }`
  - Excel：`{ excel: { sheet, cell } }`
- 返回：影响范围节点列表（包含 UI/Excel/指标坐标）。

## 6. 前端标记逻辑

- 点击单元格或指标后调用预览接口。
- 返回节点中含 `ui` 坐标者，高亮黄色边框。
- 文档点击清空标记，避免残留高亮。
