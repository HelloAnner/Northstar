# 撤销能力设计（会话内）

日期：2026-02-04

## 目标
- 将顶部“重置”改为“撤销”，执行“撤销上一步操作的数据变化”。
- 撤销仅在当前会话有效（刷新/重启失效）。
- 支持多次连续撤销。
- 导入不支持撤销（导入完成清空撤销栈）。

## 方案选择
采用“前端差异栈（Undo Stack）+ 批量回写”方案：
- 每个用户交互动作形成一个撤销步骤。
- 步骤记录该动作造成的字段级 diff（before/after）。
- 撤销时反向回写 diff，并重算指标。

## 范围与边界
- 覆盖操作：明细单元格编辑、指标单项调整、智能调整、撤销本身。
- 不覆盖：导入（导入完成后清空栈）。
- “一步”定义：一次用户交互动作（如单元格失焦/回车、点击智能调整、点击单项应用）。

## 数据结构
前端新增 `undoStore`：
- `stack: UndoStep[]`
- `canUndo: boolean`
- `push(step)` / `pop()` / `clear()`

UndoStep：
- `type`: `cell | indicator | optimize | undo`
- `summary`: 文本摘要（用于调试/提示）
- `changes`: `[{ companyId, fields: { key: { before, after } } }]`
- `createdAt`: 时间戳

## 关键流程
1) **单元格编辑**
- 提交前读取旧值；PATCH 成功后，用返回行与旧值计算 diff 入栈。

2) **指标单项调整 / 智能调整**
- 动作前拉取全量企业数据（必要字段）。
- 动作后再次拉取，比较生成 diff 入栈。

3) **撤销**
- 取栈顶 diff，反向构建批量更新请求；成功后出栈并刷新指标/表格。

4) **导入**
- 导入成功后清空撤销栈。

## 接口改造
新增后端批量更新接口：
- `PATCH /api/companies/batch`
- 入参：`{ updates: [{ id, patch }] }`
- 执行：逐条更新后仅 `RecalcAll` 一次，返回 `groups`。

## 异常处理
- 撤销失败：不出栈，提示失败信息。
- 批量更新失败：整体失败返回，前端保持栈不变。

## 测试要点
- 单元格编辑 → 撤销 → 数值恢复。
- 智能调整 → 撤销 → 数值恢复。
- 连续多次撤销。
- 导入后撤销不可用（栈清空）。
- 月份切换后撤销不可用（栈清空）。
