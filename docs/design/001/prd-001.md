## 1. 项目背景

**Northstar** 是一个经济数据统计系统，核心职责是处理批发、零售、住宿、餐饮四大行业的月度统计数据，从 Excel 预估表导入 → 企业数据管理与微调 → 指标联动计算 → 定稿 Excel 导出，形成完整的数据处理闭环。

### 1.1 使用场景

- 统计人员每月收集各行业企业的销售/零售/营业数据
- 将数据从预估 Excel 表导入系统
- 在系统中对单企业或全局指标进行微调（手工编辑或智能联动调整）
- 核验 16 项关键指标是否达到目标区间
- 导出定稿 Excel 报表，与固定模板保持 1:1 一致

### 1.2 版本架构

当前为 **V3**：单项目制、SQLite 文件数据库、一键自动导入、API 端口 20261。

## 2. 行业与数据结构

### 2.1 四大行业

| 行业 | 类型标识 | 数据表 | 企业 ID 前缀 |
|------|----------|--------|--------------|
| 批发业 | `wholesale` | `wholesale_retail` | `wr:{id}` |
| 零售业 | `retail` | `wholesale_retail` | `wr:{id}` |
| 住宿业 | `accommodation` | `accommodation_catering` | `ac:{id}` |
| 餐饮业 | `catering` | `accommodation_catering` | `ac:{id}` |

批发/零售（WR）共用同一张表，住宿/餐饮（AC）共用同一张表，通过 `industry_type` 字段区分。

### 2.2 企业标记

- `company_scale`：企业规模（1=大、2=中、3=小、4=微），用于反向调整权重
- `is_eat_wear_use`：是否属于"吃穿用"品类，用于专项增速计算
- `is_small_micro`：是否为小微企业，用于小微增速计算

## 3. 明细字段（UI 与 Excel 全量）

### 3.1 WR 批零明细字段

**销售额系列：**
- `salesPrevMonth`：上月销售额
- `salesCurrentMonth`：本月销售额（主要输入字段）
- `salesLastYearMonth`：上年同期销售额
- `salesYoYDiff`：销售同比增量（派生）
- `salesMoMDiff`：销售环比增量（派生）
- `salesMoMRate`：销售环比增速（派生）
- `salesMonthRate`：销售当月同比增速（派生）
- `salesCurrentCumulative`：本年累计销售额
- `salesLastYearCumulative`：上年累计销售额
- `salesCumulativeYoYDiff`：累计同比增量（派生）
- `salesCumulativeRate`：累计同比增速（派生）

**零售额系列（结构同销售额）：**
- `retailPrevMonth` / `retailCurrentMonth` / `retailLastYearMonth`
- `retailYoYDiff` / `retailMoMDiff` / `retailMoMRate` / `retailMonthRate`
- `retailCurrentCumulative` / `retailLastYearCumulative`
- `retailCumulativeYoYDiff` / `retailCumulativeRate`

**其他：**
- `retailRatio`：零售比（`retailCurrentMonth / salesCurrentMonth * 100`，派生）
- `companyScale` / `flags` / `sourceSheet`

### 3.2 AC 住餐明细字段

除营业额（类比销售额）系列外，额外包含住餐拆分字段：

- `roomCurrentMonth` / `roomLastYearMonth` / `roomCurrentCumulative` / `roomLastYearCumulative`：客房营业额（仅 Excel 坐标，不展示在 UI）
- `foodCurrentMonth` / `foodLastYearMonth` / `foodCurrentCumulative` / `foodLastYearCumulative`：食品零售额
- `goodsCurrentMonth` / `goodsLastYearMonth` / `goodsCurrentCumulative` / `goodsLastYearCumulative`：商品零售额
- `retailCurrentMonth`：零售额 = `food + goods`（联动派生，AC 特有）

## 4. 16 项核心指标

### 4.1 指标总览

| 分组 | 指标 ID | 指标名称 | 单位 |
|------|---------|----------|------|
| 限上社零额 | `limitAbove_month_value` | 限上社零额（当月值） | 万元 |
| 限上社零额 | `limitAbove_month_rate` | 限上社零额增速（当月） | % |
| 限上社零额 | `limitAbove_cumulative_value` | 限上社零额（累计值） | 万元 |
| 限上社零额 | `limitAbove_cumulative_rate` | 限上社零额增速（累计） | % |
| 专项增速 | `eatWearUse_month_rate` | 吃穿用增速（当月） | % |
| 专项增速 | `microSmall_month_rate` | 小微企业增速（当月） | % |
| 四大行业 | `wholesale_month_rate` | 批发业销售额增速（当月） | % |
| 四大行业 | `wholesale_cumulative_rate` | 批发业销售额增速（累计） | % |
| 四大行业 | `retail_month_rate` | 零售业销售额增速（当月） | % |
| 四大行业 | `retail_cumulative_rate` | 零售业销售额增速（累计） | % |
| 四大行业 | `accommodation_month_rate` | 住宿业营业额增速（当月） | % |
| 四大行业 | `accommodation_cumulative_rate` | 住宿业营业额增速（累计） | % |
| 四大行业 | `catering_month_rate` | 餐饮业营业额增速（当月） | % |
| 四大行业 | `catering_cumulative_rate` | 餐饮业营业额增速（累计） | % |
| 社零总额 | `totalSocial_cumulative_value` | 社零总额（累计值） | 万元 |
| 社零总额 | `totalSocial_cumulative_rate` | 社零总额增速（累计） | % |

### 4.2 指标计算口径

**限上社零额（当月/累计）：**
- WR：汇总所有企业 `retailCurrentMonth` / `retailCurrentCumulative`
- AC：汇总所有企业 `foodCurrentMonth + goodsCurrentMonth` / 对应累计
- 增速 = `(current - lastYear) / lastYear * 100`

**四大行业增速：**
- WR（批发/零售）：基于 `salesCurrentMonth` vs `salesLastYearMonth`
- AC（住宿/餐饮）：基于 `revenueCurrentMonth` vs `revenueLastYearMonth`
- 累计口径类同

**吃穿用增速：** 仅统计 `is_eat_wear_use=1` 的 WR 企业零售额

**小微增速：** 仅统计 `is_small_micro=1` 的 WR 企业零售额

**社零总额（累计）：**
```
totalSocial = limitAbove累计 + 估算限下累计
估算限下 = last_year_limit_below_cumulative × (1 + microSmallRate/100)
增速 = (totalSocial - lastYearTotal) / lastYearTotal * 100
```

## 5. DAG 联动规则

### 5.1 正向联动边（数据修改时触发）

**WR 字段正向依赖：**
- `salesCurrentMonth` / `salesLastYearMonth` → `salesMonthRate`
- `salesCurrentMonth` → `salesCurrentCumulative`
- `salesLastYearMonth` → `salesLastYearCumulative`
- `retailCurrentMonth` + `salesCurrentMonth` → `retailRatio`
- 各字段 → 行业聚合 → 全局汇总 → 指标节点

**AC 字段特殊联动：**
- `foodCurrentMonth + goodsCurrentMonth` → `retailCurrentMonth`
- `foodLastYearMonth + goodsLastYearMonth` → `retailLastYearMonth`

**累计联动规则：**
- `currentCumulative = prevCumulative + currentMonth`（仅当用户未手动设置累计时）

### 5.2 反向联动（指标/汇总修改时触发）

指标或行业汇总节点被修改时，系统反向随机分配调整量到 L0/L1 原始字段，再正向重算。

**调整策略：**

| 目标类型 | 调整策略 |
|----------|----------|
| 增速类（当月） | 只调整当月值，上年同期不变 |
| 增速类（累计） | 只调整当月值，联动更新累计 |
| 值/汇总类 | 按权重随机分配到企业 |
| 派生差值/比值字段 | 只调整当月值 |

**权重规则：** 行业占比 50% + 企业规模 50%（加权随机）
**约束：** 仅保证非负；无单企业调整上限；允许每次结果不同

**社零总额特殊路径：**
- 改动量按 limitAbove / limitBelow **50/50** 分摊
- limitBelow 通过反算配置项 `last_year_limit_below_cumulative` 实现

### 5.3 联动高亮预览

用户点击任意单元格或指标，系统通过 BFS（同时沿正向边 + 反向边传播）计算所有联动节点，前端以**黄色边框**标记。点击空白处清除高亮。

## 6. Excel 导入导出

### 6.1 导入流程

```
上传 Excel → Sheet 识别与确认 → 月份选择 → 企业数据解析
→ 写入 raw 层（sheet_cells/sheet_columns/sheet_rows）
→ 写入业务表（wholesale_retail / accommodation_catering）
→ 重算派生字段 + 指标 → 清空撤销栈
```

Sheet 类型：批零主表 / 住餐主表 / 批零快照 / 住餐快照 / 吃穿用 / 小微 / 汇总

### 6.2 导出流程

- 从内嵌定稿模板（gzip+base64 编码）克隆工作簿
- 按 DAG Excel 坐标映射写入企业数据 + 行业汇总 + 指标
- 模板公式单元格保留公式，不覆盖
- 模板年份自动替换为当前统计年份

### 6.3 关键 Excel 坐标

**批零模板企业列（WR，列 D~O）：**
- D：salesCurrentMonth，E：salesLastYearMonth，F：salesMonthRate
- G：salesCurrentCumulative，H：salesLastYearCumulative，I：salesCumulativeRate
- J：retailCurrentMonth，K：retailLastYearMonth，L：retailMonthRate
- M：retailCurrentCumulative，N：retailLastYearCumulative，O：retailCumulativeRate

**住餐模板企业列（AC，列 D~Y）：**
- D~I：同批零销售额部分
- J~M：客房（room）；N~Q：食品（food）；R~U：商品（goods）；V~Y：零售额（retail）

**汇总表（定）关键指标坐标（行 4）：**
- G4：limitAbove_month_value，S4：limitAbove_month_rate
- I4：limitAbove_cumulative_value，T4：limitAbove_cumulative_rate
- K4：wholesale_month_rate，L4：wholesale_cumulative_rate
- M4：retail_month_rate，N4：retail_cumulative_rate
- O4：accommodation_month_rate，P4：accommodation_cumulative_rate
- Q4：catering_month_rate，R4：catering_cumulative_rate
- U4：eatWearUse_month_rate，V4：microSmall_month_rate
- N10：totalSocial_cumulative_value，S10：totalSocial_cumulative_rate

## 7. 撤销功能

- 范围：单元格编辑、指标单项调整、智能调整（导入不可撤销）
- 仅会话内有效；支持多步连续撤销
- 每步记录 `{ companyId, fields: { key: { before, after } } }`
- 撤销时反向批量写回，调用 `PATCH /api/companies/batch`，成功后重算
