## 一、项目背景

**Northstar** 是月度经济数据统计系统，处理批发、零售、住宿、餐饮四大行业的月度数据，完整流程：

```
预估 Excel 导入 → 企业数据管理 / 微调 → 指标联动计算 → 定稿 Excel 导出
```

**当前版本（V3）：** 单项目制、SQLite 文件数据库、一键自动导入，API 端口 20261。

## 三、明细字段全量（含 DAG 节点）

> 以下 ColumnKey 全部是 DAG 节点。UI 全覆盖字段在前端表格展示，非 UI 字段仅用于 Excel 坐标映射。

### 3.1 WR（批零）UI 字段

**销售额系列：**
- `salesPrevMonth`：上月销售额
- `salesCurrentMonth`：本月销售额（主要输入，L0 原始字段）
- `salesLastYearMonth`：上年同期销售额（L0 原始字段）
- `salesYoYDiff`：销售同比增量（派生）
- `salesMoMDiff`：销售环比增量（派生）
- `salesMoMRate`：销售环比增速（派生）
- `salesMonthRate`：销售当月同比增速（派生）
- `salesCurrentCumulative`：本年累计销售额
- `salesLastYearCumulative`：上年累计销售额
- `salesCumulativeYoYDiff`：累计同比增量（派生）
- `salesCumulativeRate`：累计同比增速（派生）

**零售额系列（结构同销售额）：**
- `retailPrevMonth` / `retailCurrentMonth` / `retailLastYearMonth`
- `retailYoYDiff` / `retailMoMDiff` / `retailMoMRate` / `retailMonthRate`
- `retailCurrentCumulative` / `retailLastYearCumulative`
- `retailCumulativeYoYDiff` / `retailCumulativeRate`

**其他 UI 字段：**
- `retailRatio`：零售比 = `retailCurrentMonth / salesCurrentMonth * 100`（派生）
- `companyScale`：企业规模标记
- `flags`：吃穿用/小微标记
- `sourceSheet`：数据来源 Sheet

### 3.2 AC（住餐）UI 字段

除营业额系列（类比 WR 销售额，字段名为 `salesCurrentMonth` 等，但 DB 存储为 `revenue_*`）外，额外包含：

- `retailCurrentMonth`：零售额 = `food + goods`（DAG 联动派生，AC 特有）
- `retailLastYearMonth`：上年同期零售额 = `foodLastYear + goodsLastYear`

### 3.3 AC（住餐）非 UI 字段（仅 Excel 坐标映射）

- `roomCurrentMonth` / `roomLastYearMonth` / `roomCurrentCumulative` / `roomLastYearCumulative`：客房营业额
- `foodCurrentMonth` / `foodLastYearMonth` / `foodCurrentCumulative` / `foodLastYearCumulative`：食品（餐费）零售额
- `goodsCurrentMonth` / `goodsLastYearMonth` / `goodsCurrentCumulative` / `goodsLastYearCumulative`：商品销售零售额

### 4.1 指标总览

| 分组 | 指标 ID | 指标名称 | 单位 |
|------|---------|----------|------|
| 限上社零额 | `limitAbove_month_value` | 限上社零额（当月值） | 万元 |

| 限上社零额 | `limitAbove_cumulative_value` | 限上社零额（累计值） | 万元 |
| 限上社零额 | `limitAbove_cumulative_rate` | 限上社零额增速（累计） | % |
| 专项增速 | `eatWearUse_month_rate` | 吃穿用增速（当月） | % |
| 专项增速 | `microSmall_month_rate` | 小微企业增速（当月） | % |
| 四大行业 | `wholesale_month_rate` | 批发业销售额增速（当月） | % |

| 四大行业 | `retail_month_rate` | 零售业销售额增速（当月） | % |
| 四大行业 | `retail_cumulative_rate` | 零售业销售额增速（累计） | % |
| 四大行业 | `accommodation_month_rate` | 住宿业营业额增速（当月） | % |
| 四大行业 | `accommodation_cumulative_rate` | 住宿业营业额增速（累计） | % |
| 四大行业 | `catering_month_rate` | 餐饮业营业额增速（当月） | % |
| 四大行业 | `catering_cumulative_rate` | 餐饮业营业额增速（累计） | % |
| 社零总额 | `totalSocial_cumulative_value` | 社零总额（累计值） | 万元 |
| 社零总额 | `totalSocial_cumulative_rate` | 社零总额增速（累计） | % |

### 4.2 指标计算口径

**限上社零额：**
- 当月值 = Σ（WR `retailCurrentMonth`）+ Σ（AC `foodCurrentMonth + goodsCurrentMonth`）
- 累计值 = Σ（WR `retailCurrentCumulative`）+ Σ（AC `foodCurrentCumulative + goodsCurrentCumulative`）
- 增速 = `(current - lastYear) / lastYear * 100`

**四大行业增速：**
- WR（批发/零售）：基于 `salesCurrentMonth` vs `salesLastYearMonth`（累计同理）
- AC（住宿/餐饮）：基于 `revenueCurrentMonth` vs `revenueLastYearMonth`（累计同理）

**吃穿用增速：**
- 仅统计 `is_eat_wear_use = 1` 的 WR 企业 `retailCurrentMonth` / `retailLastYearMonth`

**小微增速：**
- 仅统计 `is_small_micro = 1` 的 WR 企业 `retailCurrentMonth` / `retailLastYearMonth`

**社零总额（累计）：**
```
估算限下累计 = last_year_limit_below_cumulative × (1 + microSmallRate / 100)
totalSocial = limitAbove累计 + 估算限下累计
增速 = (totalSocial - lastYearTotal) / lastYearTotal * 100
```
其中 `lastYearTotal = Σ(WR retailLastYearCumulative) + Σ(AC foodLastYear + goodsLastYear) + last_year_limit_below_cumulative`

## 五、DAG 节点定义

### 5.1 节点命名规则

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 企业字段 | `wr:{id}:{field}` / `ac:{id}:{field}` | `wr:1:salesCurrentMonth` |
| 行业聚合 | `industry:{type}:{metric}` | `industry:wholesale:salesCurSum` |
| 全局汇总 | `aggregate:{metric}` | `aggregate:limitAboveRetailCurSum` |
| 指标 | `indicator:{id}` | `indicator:limitAbove_month_rate` |

### 5.2 行业聚合节点（L2）

`industry:{type}:{metric}`，其中 metric 包括：
- `salesCurSum` / `salesLastSum`：当月/上年销售额汇总
- `salesCurCumSum` / `salesLastCumSum`：累计销售额汇总
- `retailCurSum` / `retailLastSum`：当月/上年零售额汇总
- `retailCurCumSum` / `retailLastCumSum`：累计零售额汇总
- `salesMonthRate` / `salesCumulativeRate`：行业增速

### 5.3 全局汇总节点（L2/L3）

`aggregate:{metric}`，其中 metric 包括：
- `limitAboveRetailCurSum` / `limitAboveRetailLastSum`：限上零售额当月汇总
- `limitAboveRetailCurCumSum` / `limitAboveRetailLastCumSum`：限上零售额累计汇总
- `limitAboveRetailMonthRate` / `limitAboveRetailCumulativeRate`：限上零售增速
- `eatWearUseRetailCurSum` / `eatWearUseRetailLastSum`：吃穿用零售额汇总
- `microSmallRetailCurSum` / `microSmallRetailLastSum`：小微零售额汇总

## 六、DAG 依赖边规则

### 6.1 正向边：企业字段内部（WR）

```
salesCurrentMonth  → salesMonthRate, salesYoYDiff, salesMoMDiff, salesMoMRate
salesLastYearMonth → salesMonthRate, salesYoYDiff
salesPrevMonth     → salesMoMDiff, salesMoMRate
salesCurrentMonth  → salesCurrentCumulative
salesLastYearMonth → salesLastYearCumulative
salesCurrentCumulative + salesLastYearCumulative → salesCumulativeRate, salesCumulativeYoYDiff

retailCurrentMonth  → retailMonthRate, retailYoYDiff, retailMoMDiff, retailMoMRate, retailRatio
retailLastYearMonth → retailMonthRate, retailYoYDiff
retailPrevMonth     → retailMoMDiff, retailMoMRate
salesCurrentMonth   → retailRatio（分母）
retailCurrentMonth  → retailCurrentCumulative
retailLastYearMonth → retailLastYearCumulative
retailCurrentCumulative + retailLastYearCumulative → retailCumulativeRate, retailCumulativeYoYDiff
```

### 6.2 正向边：AC 住餐特殊联动

```
foodCurrentMonth + goodsCurrentMonth   → retailCurrentMonth（AC 零售额派生）
foodLastYearMonth + goodsLastYearMonth → retailLastYearMonth
foodCurrentCumulative + goodsCurrentCumulative   → retailCurrentCumulative
foodLastYearCumulative + goodsLastYearCumulative → retailLastYearCumulative

salesCurrentMonth → salesCurrentCumulative
salesLastYearMonth → salesLastYearCumulative
```

### 6.3 正向边：企业字段 → 行业聚合

每个 WR/AC 企业字段连向所属行业的聚合节点：
```
wr:{id}:salesCurrentMonth   → industry:{type}:salesCurSum
wr:{id}:salesLastYearMonth  → industry:{type}:salesLastSum
wr:{id}:salesCurrentCumulative  → industry:{type}:salesCurCumSum
wr:{id}:salesLastYearCumulative → industry:{type}:salesLastCumSum

wr:{id}:retailCurrentMonth  → industry:{type}:retailCurSum
                            → aggregate:limitAboveRetailCurSum（全部 WR）
                            → aggregate:eatWearUseRetailCurSum（仅 is_eat_wear_use=1）
                            → aggregate:microSmallRetailCurSum（仅 is_small_micro=1）
```

### 6.4 正向边：行业聚合/全局汇总 → 指标

```
industry:wholesale:salesCurSum + salesLastSum   → indicator:wholesale_month_rate
industry:wholesale:salesCurCumSum + salesLastCumSum → indicator:wholesale_cumulative_rate
（零售/住宿/餐饮同理）

aggregate:limitAboveRetailCurSum  → indicator:limitAbove_month_value
aggregate:limitAboveRetailCurSum + limitAboveRetailLastSum → indicator:limitAbove_month_rate
aggregate:limitAboveRetailCurCumSum → indicator:limitAbove_cumulative_value
aggregate:limitAboveRetailCurCumSum + limitAboveRetailLastCumSum → indicator:limitAbove_cumulative_rate

aggregate:eatWearUseRetailCurSum + eatWearUseRetailLastSum → indicator:eatWearUse_month_rate
aggregate:microSmallRetailCurSum + microSmallRetailLastSum → indicator:microSmall_month_rate
```

### 6.5 正向边：指标间依赖（社零总额链路）

```
indicator:limitAbove_cumulative_value → indicator:totalSocial_cumulative_value
indicator:microSmall_month_rate       → indicator:totalSocial_cumulative_value（用于估算限下）
indicator:totalSocial_cumulative_value → indicator:totalSocial_cumulative_rate
aggregate:limitAboveRetailLastCumSum   → indicator:totalSocial_cumulative_rate（分母）
```

### 6.6 反向边（联动预览专用，高亮输入来源）

```
// 企业增速字段反查输入字段
wr:{id}:salesMonthRate     ← salesCurrentMonth, salesLastYearMonth
wr:{id}:salesCumulativeRate ← salesCurrentCumulative, salesLastYearCumulative
wr:{id}:retailMonthRate    ← retailCurrentMonth, retailLastYearMonth
wr:{id}:retailCumulativeRate ← retailCurrentCumulative, retailLastYearCumulative

// AC 零售额反查食品+商品
ac:{id}:retailCurrentMonth  ← foodCurrentMonth, goodsCurrentMonth
ac:{id}:retailLastYearMonth ← foodLastYearMonth, goodsLastYearMonth

// 指标反查企业明细字段
indicator:limitAbove_month_value / month_rate ← wr/ac:{id}:retailCurrentMonth（全量）
indicator:limitAbove_cumulative_value / cumulative_rate ← wr/ac:{id}:retailCurrentCumulative（全量）
indicator:wholesale_month_rate     ← wr:{id}:salesCurrentMonth（批发企业）
indicator:wholesale_cumulative_rate ← wr:{id}:salesCurrentCumulative（批发企业）
indicator:retail_month_rate        ← wr:{id}:salesCurrentMonth（零售企业）
indicator:accommodation_month_rate ← ac:{id}:salesCurrentMonth（住宿企业）
indicator:catering_month_rate      ← ac:{id}:salesCurrentMonth（餐饮企业）

// 社零总额反查限上指标
indicator:totalSocial_cumulative_value ← indicator:limitAbove_cumulative_value
indicator:totalSocial_cumulative_rate  ← indicator:limitAbove_cumulative_rate

// 吃穿用/小微：仅对应标记企业
indicator:eatWearUse_month_rate ← wr:{id}:retailCurrentMonth（is_eat_wear_use=1）
indicator:microSmall_month_rate ← wr:{id}:retailCurrentMonth（is_small_micro=1）
```

## 七、联动调整偏好规则

> 来源：`docs/dag-preferences.md` + `docs/plans/2026-02-04-dag-unified-engine-design.md`

### 7.1 总体原则

- **企业字段被修改**：只做正向重算后代，同时高亮全部受影响的汇总/指标节点。
- **行业/汇总/指标被修改**：触发反向随机分配 → 正向重算子节点。
- 反向随机只作用于未被用户明确修改的 L0/L1 原始字段。

### 7.2 反向调整策略（按目标类型）

| 目标类型 | 调整策略 |
|----------|----------|
| 增速类（当月） | 只调整当月值，上年同期不动 |
| 增速类（累计） | 只调整本年当月值，通过"累计 = 上月累计 + 当月"联动更新累计，历史月份不动 |
| 值/汇总类指标 | 按权重随机分配调整量到各企业 L0 字段 |
| 派生差值/比值字段（同比增量、环比增量、零销比）被编辑 | 只调整本年本月值 |
| 累计值类指标被编辑 | 直接调整当月值，再由"累计 = 上月 + 当月"推导 |

### 7.3 随机分配权重

```
weight[i] = 0.5 × 行业占比[i] + 0.5 × 规模权重[i]
           再乘以 jitter ∈ [0.7, 1.3]（防止完全比例分配）
value[i]  = round(weight[i] / Σweight × target)
// 最后修正舍入差
```

### 7.4 约束与边界

- **参与企业范围**：目标所涉及行业的全部企业；跨行业指标覆盖所有相关行业。
- **约束**：只保证非负（截断为 0），无单企业调整上限。
- **随机性**：允许每次结果不同，不要求可重复。
- **锁定机制**：不启用（不锁定任何字段/企业）。

### 7.5 多父节点指标（社零总额）

- 涉及两条父链路：limitAbove / limitBelow（估算限下）。
- 调整量 **50/50 分摊** 给两条链路。
- limitBelow 通过反算配置项 `last_year_limit_below_cumulative` 实现，保证非负。

### 7.6 高亮范围

- 企业字段被编辑：高亮该企业字段的全部后代 + 全部受影响行业/指标节点（BFS 正向）。
- 指标/汇总节点被编辑：高亮全部祖先（BFS 反向） + 全部后代（BFS 正向）。

## 八、联动预览（高亮标记）

### 8.1 BFS 传播算法

```
1. 从锚点节点出发
2. 同时沿正向边（Edges）+ 反向边（ReverseEdges）进行 BFS
3. 收集全部可达节点
4. 映射为 ImpactNode { nodeId, ui?, indicatorId?, excel? }
5. 结果按 nodeId 排序（保证前端渲染稳定）
```

### 8.2 接口协议

```
POST /api/linkage/preview

入参（三选一）：
  { ui: { rowId: "wr:1", columnKey: "salesCurrentMonth" } }
  { indicatorId: "limitAbove_month_rate" }
  { excel: { sheet: "批零总表", cell: "D5" } }

返回：[
  { nodeId, ui?: { rowId, columnKey }, indicatorId?, excel?: [{ sheet, cell }] }
]
```

### 8.3 UI 锚点解析

- 前端点击单元格时，以 `{rowId}|{columnKey}` 查找 DAG 节点（UIIndex）。
- 前端点击指标时，以 `indicator:{id}` 作为锚点。
- 返回节点中含 `ui` 坐标者，高亮黄色边框；点击空白处清除高亮。

- 读取模板列 C 的行业码，扫描至空行结束，建立"行业码 → 行号"索引（TemplateIndex）。

sumRow    = maxRow + 1   // 行业合计行

模板内以下单元格含公式，导出时只写入输入单元格，公式由 Excel 自行计算：
- `K3 = E18-E21`（上月限上零售额）
- `K5 = E19-E22`（上年同期上月）
- `K7 = K3-K4`（上月限下）
- `K8 = K5-K6`（上年同期上月限下）
- `K9 = (K7-K8)/K8*100`（限下增速）
- `K12 = E20-E23`（当月社零额）
- `K15 = K14*(1+K11/100)`（当月估算限下）
- `K17 = K15+K16`（当月社零总额）
- `K19 = (K17-K18)/K18*100`（当月增速）
- `K21 = K20+K17`（累计社零总额）
- `K23 = (K21-K22)/K22*100`（累计增速）

**汇总表（定）A11** 含 CONCAT 长公式，自动生成报表文案，引用 B4/D10/K4/M4/O4/Q4/G4/S4/I4/T4/N10/S10，导出时保留公式，X3 按此公式逻辑拼接。

## 十、Excel 导入流程

### 10.1 导入步骤

```
1. 上传预估 Excel 文件
2. Sheet 识别（按列名相似度计算命中率）
3. 返回识别结果 + 可选月份列表（人工确认）
4. 解析：主表 + 快照 → CanonicalCompany
5. 写入 raw 层（sheet_cells / sheet_columns / sheet_rows）
6. 写入业务表（wholesale_retail / accommodation_catering）
7. 重算派生字段 + 指标
8. 清空撤销栈
```

### 10.2 Sheet 类型识别

| Sheet 类型 | 标识 |
|------------|------|
| 批零主表（批发/零售分表） | `wholesale_main` / `retail_main` |
| 住餐主表（住宿/餐饮分表） | `accommodation_main` / `catering_main` |
| 批零快照 | 含 `年月` 字样 + 批零结构 |
| 住餐快照 | 含 `年月` 字样 + 住餐结构 |
| 吃穿用 | `eat_wear_use` |
| 小微 | `small_micro` |
| 汇总/社零额 | 模板固定 Sheet |

### 10.3 数据层架构

- **raw 层**：`sheet_cells` / `sheet_columns` / `sheet_rows`，保存原始单元格值/公式/格式
- **业务层**：`wholesale_retail` / `accommodation_catering`，标准化业务字段
- **summary 层**：`summary_*`，汇总 Sheet 业务解析结果

## 十一、导出规则

### 11.1 导出策略

- 从内嵌定稿模板（gzip+base64 内嵌 Go 文件）克隆工作簿
- 按 DAG 坐标映射写入各企业字段、行业汇总行、指标单元格
- **公式单元格保留公式，不写入数值**
- 模板中年份常量（2025/2024）按导出年份自动替换为 `year / year-1`
- 导出前对账：summary 数据与实时计算差异仅提示，不阻断导出

### 11.2 导出一致性关键规则

- 社零额（定）的 K4/K6/K13/K16 必须写入，否则整个公式链失效
- 汇总表（定）A11 保留公式，X3 按 A11 相同逻辑拼接文案
- 汇总表（定）A1 标题随年月更新（否则模板月份引用计算错误）
- 增速值一律取 `(current - lastYear) / lastYear * 100`，`lastYear=0` 时写 `-100`

## 十二、撤销功能

### 12.1 功能范围

| 操作 | 是否支持撤销 |
|------|------------|
| 单元格编辑 | ✅ |
| 指标单项调整 | ✅ |
| 智能调整（全局） | ✅ |
| Excel 导入 | ❌（导入后清空撤销栈） |

- 仅当前会话有效（刷新/重启失效）
- 支持多步连续撤销
- 月份切换后清空撤销栈

### 12.2 数据结构

前端 `undoStore` 维护 `UndoStep[]` 栈：

```typescript
interface UndoStep {
  type: 'cell' | 'indicator' | 'optimize' | 'undo'
  summary: string   // 调试/提示文本
  changes: Array<{
    companyId: string   // "wr:1" 或 "ac:2"
    fields: Record<string, { before: unknown; after: unknown }>
  }>
  createdAt: number
}
```

### 12.3 撤销流程

1. 编辑前记录旧值（或操作前拉取全量快照）
2. 操作成功后计算 diff（仅变化字段）→ `undoStore.push(step)`
3. 点击"撤销"：取栈顶 diff，反向构建批量更新请求
4. `PATCH /api/companies/batch { updates: [{ id, patch }] }`
5. 后端逐条更新后执行一次 `RecalcAll`，返回 `groups`
6. 前端刷新表格 + 指标，出栈

### 12.4 后端批量更新接口

```
PATCH /api/companies/batch
入参：{ updates: [{ id: "wr:1", patch: { salesCurrentMonth: 100, ... } }] }
返回：{ groups: [...] }（重算后的指标分组）
```
支持 WR + AC 字段，包括 room/food/goods 的 `*_current_cumulative`。
